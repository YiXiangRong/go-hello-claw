# go-tiny-claw - 极简工业级 Harness 引擎

> 用 Go 吸收顶级开源项目 OpenClaw 的极简哲学，从零构建工业级 harness 引擎

## 🌟 项目简介

go-tiny-claw 是一个受 OpenClaw 启发的极简工业级 Harness 引擎，采用 Go 语言构建。它提供了一个强大的框架，让 AI 模型能够通过工具执行实际的操作任务。


## 核心设计哲学
Harness over Framework: 真正的壁垒不在于调用大模型 API，而在于如何调度工具、管理上下文和安全拦截。
极简即是正义: 我们拒绝臃肿的插件，仅向大模型提供 Read、Write、Edit 和 Bash 四大图灵完备的原语。
状态外部化: 抛弃内存状态机，将记忆与计划持久化在 PLAN.md 与 TODO.md 中。
当前系统组件
心脏 (Main Loop): 纯手写的 ReAct 循环。
大脑 (Provider): 适配了官方 Claude SDK 与智谱 GLM API。
手脚 (Tool Registry): 支持并发执行的动态工具集。
神经元 (Reporter): 已成功接入飞书群聊事件流。

### 核心特性

- **极简设计**: 遵循 OpenClaw 的极简哲学，代码结构清晰简洁
- **双引擎支持**: 支持 OpenAI 和 Claude 两种 LLM 提供商
- **工具系统**: 完整的工具注册和执行机制
- **双阶段思考**: 支持慢思考模式，强制模型进行规划
- **安全操作**: 文件操作、命令执行等工具都有完善的错误处理

## 🏗️ 架构设计

```
go-tiny-claw/
├── cmd/claw/          # 主程序入口
├── internal/
│   ├── engine/        # 引擎核心逻辑
│   ├── provider/      # LLM 提供商接口
│   ├── tools/         # 工具系统
│   └── schema/        # 数据结构定义
└── README.md
```

### 核心组件

#### 1. AgentEngine (`internal/engine/loop.go`)
- **双阶段执行**: Thinking Phase + Action Phase
- **工具管理**: 通过 Registry 管理可用工具
- **上下文维护**: 维护对话历史和工具调用记录

#### 2. LLM Provider (`internal/provider/`)
- **统一接口**: `LLMProvider` 接口定义
- **多提供商**: 支持 OpenAI 和 Claude
- **智能路由**: 自动适配不同提供商的 API 格式

#### 3. 工具系统 (`internal/tools/`)
- **工具注册**: Registry 负责工具的注册和管理
- **工具执行**: 支持异步执行和错误处理
- **智能匹配**: EditFile 工具支持模糊匹配

#### 4. 工具列表

| 工具名称 | 描述 | 特点 |
|---------|------|------|
| `read_file` | 读取文件内容 | 支持路径相对化，自动截断长内容 |
| `write_file` | 写入文件内容 | 自动创建目录，支持覆盖写入 |
| `bash` | 执行 bash 命令 | 支持链式命令，30秒超时保护 |
| `edit_file` | 智能编辑文件 | 支持模糊匹配，多层级匹配策略 |

## 🚀 快速开始

### 环境要求

- Go 1.18+
- ZHIPU_API_KEY (智谱 AI API Key)

### 安装和配置

1. 克隆项目
```bash
git clone <repository-url>
cd go-tiny-claw
```

2. 设置环境变量
```bash
export ZHIPU_API_KEY="your-api-key-here"
```

3. 运行程序
```bash
go run cmd/claw/main.go
```

## 🔧 核心特性详解

### 双阶段思考模式

引擎采用双阶段执行模式：

1. **Thinking Phase**: 剥夺工具访问权，强制模型进行思考和规划
2. **Action Phase**: 恢复工具访问权，让模型执行具体操作

这种设计确保了模型在执行任务前进行充分的思考。

### 智能工具匹配

`edit_file` 工具实现了多层级匹配策略：

1. **精确匹配**: 直接查找完全匹配的文本
2. **换行符归一化**: 处理不同平台的换行符差异
3. **空格修剪**: 忽略首尾空格的差异
4. **逐行去缩进**: 处理缩进不一致的情况

### 错误处理和日志

- **详细的日志记录**: 每个操作都有详细的日志输出
- **优雅的错误处理**: 工具执行失败时会返回清晰的错误信息
- **超时保护**: 命令执行有30秒超时限制
